> **权威基线声明**

> 凡本文档与上述两份文件冲突之处，以上述两份为准。本文档已按基线修订，消除内部矛盾。

## 一、设计目标

将 guizang-ppt-skill 的排版能力重构为独立智能体。**核心是还原瑞士国际主义排版体系**——极致字号对比、单一锚点色、数据可视化、仪表盘式布局。图片生成为非核心能力，当前版本不实现。

### 已验证的交付形态

| 维度 | 当前实现 | 设计目标（未来） |
|---|---|---|
| 输出格式 | **HTML only**（md_to_html） | 保持 HTML |
| 版式数量 | **8 种**（L1-L8，已实现纯文字映射） | 32 种（guizang 原始） |
| 工作流 | **单 Agent 线性 6 步** | 5 工作流拆分 |
| 主题色 | **IKB 蓝 1 套**（#002FA7） | 9 套 |
| 图片生成 | **不实现** | 可选扩展 |
| 交互效果 | `:hover`（待验证） | 基础交互 |

### PPTX 已废弃

9轮技术验证确认 `md_to_pptx` 效果极差（"几乎什么效果都没有实现"）。**当前版本只输出 HTML**，不再提供 PPTX 导出。

## 二、排版体系（已实现）

### 2.1 风格定位

当前仅实现**风格 B · 瑞士国际主义**：
- 全程无衬线（`font-family: sans-serif`，平台约束，不可指定具体字体名）
- 极致字号对比（标题 38px / 数据 32px / 正文 13px / 标签 10px）
- 越大越细（标题 weight:200，标签 weight:600）
- 单一高饱和锚点色（IKB 蓝 #002FA7）
- 1px 发丝线、直角色块、点阵装饰

风格 A（电子杂志 × 电子墨水）为未来扩展，当前不实现。

### 2.2 版式库（8 种，已实现）

详见 `layouts/layout-library.md`，所有版式使用统一 class 体系：

| 编号 | 版式 | 核心 class | 用途 |
|---|---|---|---|
| L1 | 封面页 | `.hd` `.ti` `.dt` `.ft` | 标题+副标题+日期 |
| L2 | KPI 概览 | `.sec` `.r` `.c` `.cl` `.cv` | 3-4 个关键指标卡片 |
| L3 | 条形图 | `.bs` `.bc` `.bf` `.bl` | CSS 垂直条形图 |
| L4 | 双栏看板 | `.g` `.co` `.ct` `.it` `.dot` `.pr` `.pt` `.pf` | 任务清单+进度条 |
| L5 | 数据表格 | `table` `th` `td` | 结构化数据 |
| L6 | 引言金句 | `.q` | 大字号引用 |
| L7 | 三栏内容 | `.r` `.c` `.ct` | 并列策略/方案 |
| L8 | 结束页 | `.p` `.ti` | 致谢+联系方式 |

**关于 32 种版式**：guizang 原始 skill 有 32 种版式（风格 A 10 种 + 风格 B 22 种）。当前已将其中最常用的 8 种实现为可直接渲染的 HTML+CSS 映射。其余 24 种为设计目标，待后续迭代逐步实现。

### 2.3 主题色（1 套，已实现）

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 | `#002FA7` | IKB 克莱因蓝，锚点色 |
| 背景 | `#F4F1EA` | 页面底色 |
| 卡片 | `#FFFFFF` | 卡片/数据区 |
| 正文 | `#0A0A0B` | 主文字 |
| 成功 | `#1A7F37` | 完成/正向 |
| 警告 | `#D4A017` | 进行中/警告 |
| 危险 | `#CF222E` | 待办/负向 |

**主题切换方法**：将 CSS 中所有 `#002FA7` 替换为目标主色。9 套主题色为 guizang 原始设计，当前仅实现 IKB 蓝一套。

### 2.4 字号字重阶梯（已实现）

| 角色 | 字号 | 字重 | class |
|---|---|---|---|
| 主标题 | 38px | 200 | `.ti` |
| 数据大字 | 32px | 200 | `.cv` |
| 引言 | 24px | 200 italic | `.q` |
| 正文/卡片 | 13px | 400 | 默认 |
| 章节标签 | 11px | 700 uppercase | `.sec` `.dt` |
| 卡片标签 | 10px | 400 uppercase | `.cl` `.bl` |

硬规则：字号越小字重越大；不使用 `h1/h2/h3` 元素选择器（平台会损坏），全部用 class。

## 三、智能体架构（当前实现）

### 3.1 当前实现：单 Agent 线性流程

系统提示词中实现的是**单 Agent 6 步线性流程**，不是多工作流：

```
用户输入
  → ① 理解需求（主题/页数/内容/风格）
  → ② 选择版式（从 L1-L8 中选组合）
  → ③ 生成内容（用指定 HTML 结构和 class 编写）
  → ④ 拼接 CSS（将 CSS 模板完整放在内容最前面）
  → ⑤ 调用 md_to_html（拼接后文本作为 md_text 传入）
  → ⑥ 长度控制（单次 < 1000 字符，超过则拆分多文件）
```

### 3.2 未来目标：5 工作流拆分

以下为设计目标，当前未实现为独立工作流：

| 工作流 | 职责 | 对应当前步骤 |
|---|---|---|
| WF1 需求澄清 | 7 问澄清 + 风格定位 | ① |
| WF2 版式规划与内容生成 | 版式分配 + 逐页内容 | ②③ |
| WF3 演讲备注 | 备注 + 时长规划 | 未实现 |
| WF4 质量校验 | P0-P3 检查 | 部分内置在禁忌规则中 |
| WF5 导出交付 | 调用插件 + 多文件拆分 | ④⑤⑥ |

**关于"工作流数量"的说明**：
- `system-prompt.md`：0 个独立工作流（单 Agent 线性）
- 本文档：5 个为未来拆分目标
- `hiagent-project/` 中的 7 工作流是**另一个项目**（HiAgent 工作流生成器），与本项目无关，不要混淆

## 四、CSS 技术约束（已验证，不可违反）

以下约束来自 `docs/04-技术验证记录.md` 的 9 轮平台实测，**必须严格遵守**：

### 4.1 必须做

1. 全部使用 **class 选择器**（`.p` `.hd` 等），禁止 `h1/h2/h3` 元素选择器
2. 全部使用**大写十六进制**颜色（`#002FA7`，非 `#002fa7`）
3. `font-family` 只能用 `sans-serif`，禁止逗号分隔多字体名
4. **多行格式**，每行一条 CSS 规则
5. 单次 `md_text` 总长度 **< 1000 字符**（对话粘贴模式）
6. CSS 模板放在**系统提示词**中，用户用自然语言描述需求

### 4.2 禁止做

1. 禁止单引号 `'`
2. 禁止 `@keyframes`、`animation`、`transition`
3. 禁止 CSS Grid（用 flex 替代）
4. 禁止 `clamp()`、`calc()`、`var()` 等 CSS 函数
5. 禁止渐变（`linear-gradient` 等）
6. 禁止单行压缩 CSS
7. 禁止 `<img>`、不生成图片
8. 禁止 JavaScript
9. 禁止 `<section>`、`<article>` 等语义化标签（用 `<div>`）

### 4.3 已验证可用

- `<style>` 标签透传保留
- flexbox 布局
- CSS 条形图（div + height 百分比）
- 进度条（div + width 百分比）
- 双栏/多栏布局
- 内联 `style` 属性（用于动态值如 `height:45%`）
- `:hover`（写在 CSS 中，待端到端验证）
- 原生 `<table>`

## 六、导出流程

1. 智能体根据用户需求选择版式组合（L1-L8）
2. 逐页生成 HTML 内容（使用统一 class 体系）
3. 将 CSS 模板（core.css + dashboard.css 合并）完整拼接在内容最前面
4. 调用 `md_to_html`，`md_text` = CSS + HTML 内容
5. 单次调用 < 1000 字符；多页内容拆分为多个文件，每页调用一次
6. `output_filename` 用有意义的英文名（如 `report-cover.html`）
7. 生成后向用户说明：共几个文件、每个对应哪一页
