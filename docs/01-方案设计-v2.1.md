# 归藏 PPT 设计智能体 · 完整方案设计 v2.1

> 基于 guizang-ppt-skill（github.com/op7418/guizang-ppt-skill）设计能力重构
> 适配平台：浦发银行智能体创设平台（agent.spdb.com）
> 核心插件：Markdown 转换器（MCP，已验证可用）
> 设计优先级：排版与风格为核心，图片生成为可选扩展
> 版本：v2.1 · 2026-09-12

---

## 一、设计目标与原则

### 1.1 目标

将 guizang-ppt-skill 的设计能力重构为独立智能体，内部包含多个可编排工作流。核心目标是还原 guizang 的排版体系和风格系统——双视觉系统、32 种版式、9 套主题、字号字重阶梯、主题节奏、质量校验。图片生成因平台能力限制降级为可选扩展，不进入主链路。

### 1.2 核心判断

原始 Skill 输出单文件自定义 HTML（WebGL + 定制 CSS + 演讲者运行时），平台插件输入是标准 Markdown。因此：

- 排版与风格通过内容结构、版式选择、字号层级、主题节奏来承载，这是 guizang 最核心、最可迁移的能力。
- 图片不依赖平台生图能力，改为：纯文字版式优先 + 配图提示词可选输出。
- 运行时交互（WebGL、动效、双窗口演讲者）不保留，但演讲备注和时长规划完整保留。

### 1.3 设计原则

| 原则 | 说明 |
|---|---|
| 排版即核心 | 32 种版式分配、主题节奏、字号分档、内容层级 |
| 风格即系统 | 风格 A/B 不是换色，是整套排版规则、字体性格、版式偏好的差异 |
| 纯文字优先 | 默认不生成图片，用大字号、数据表格、引用、对比制造视觉冲击 |
| 插件即出口 | 最终导出统一走 Markdown 转换器，不自行生成文件 |
| 工作流解耦 | 5 个核心工作流 + 2 个可选扩展，通过 Project Spec 传递状态 |
| 质量门阻断 | P0 不通过不导出 |
| 设计意图可追溯 | 每页输出版式标记和设计规格，弥补转换器渲染差距 |

## 二、排版与风格控制体系（核心）

### 2.1 双视觉系统

| 维度 | 风格 A · 电子杂志 × 电子墨水 | 风格 B · 瑞士国际主义 |
|---|---|---|
| 字体性格 | 衬线标题 + 非衬线正文 + 等宽元数据 | 全程无衬线（Inter + Helvetica + Noto Sans SC） |
| 版式偏好 | 图文混排、左文右图、图片网格、大引用 | 数据大字报、KPI 塔、时间线、矩阵、系统图 |
| 视觉锚点 | 大标题+留白 | 极细网格 + 点阵 + 单一高饱和锚点色 |
| 适合内容 | 叙事、观点、人文、故事 | 数据、产品、分析、方法论、科技 |
| 字号策略 | 标题衬线大字号，正文非衬线 | 极致字号对比（≥8:1），越大越细（200 weight） |
| 装饰语言 | 克制，靠字体对比和留白 | 1px 发丝线、直角色块、点阵 |

风格选择规则（WF1 自动判断）：
- 用户说杂志/人文/故事/文化 → A
- 用户说瑞士/极简/网格/数据/产品/科技 → B
- 内容含大量 KPI 数字/路线图/流程 → B
- 内容含大量叙事/观点/引用 → A
- 用户不指定 → 根据内容性质推荐，不确定时询问

### 2.2 版式体系（32 种，纯文字优先）

风格 A · 10 种版式：L1 开场封面、L2 章节幕封、L3 数据大字报、L4 左文右图（需图）、L5 图片网格（需图）、L6 Pipeline、L7 问题页、L8 大引用、L9 并列对比、L10 图文混排（需图）。纯文字覆盖率 7/10（70%）。

风格 B · 22 种锁定版式：S01 Index Cover、S02 Vertical Timeline+KPI、S03 Split Statement、S04 Six Cells、S05 Three Layers、S06 KPI Tower、S07 H-Bar Chart、S08 Duo Compare、S09 Dot Matrix Statement、S10 Split Closing、S11 Horizontal Timeline、S12 Manifesto、S13 Three Forces、S14 Loop Form、S15 Matrix+Hero Stat、S16 Multi-card Brief、S17 System Diagram、S18 Why Now、S19 Four Cards、S20 Stacked KPI Ledger、S21 Tech Spec Sheet、S22 Image Hero（需图）。纯文字覆盖率 21/22（95%）。

综合纯文字覆盖率：28/32（87.5%），剩余 4 种均有明确降级方案。

### 2.3 主题节奏控制

每页必须标记 hero dark / hero light / light / dark 之一：

- 禁止连续 3 页同主题
- 8 页+必须有 hero dark + hero light
- 不能全是 light 正文页
- 每 3-4 页插入 1 个 hero 页
- 封面默认 hero dark，数据页默认 light，大引用优先 dark

8 页节奏模板：1 hero dark 封面 → 2 light 数据 → 3 dark 对比 → 4 light 流程 → 5 hero light 幕封 → 6 dark 引用 → 7 hero dark 问题 → 8 light 收束。

### 2.4 字号与字重阶梯

中文大标题字号分档：1行≤8字→H1最大档；2行每行≤8字→H1短；2行任一行9-12字→H2；3行+→优先改写。

字重阶梯（瑞士风核心：越大越细）：
- 超大标题 200 (ExtraLight)
- 大标题 200-300
- 中标题 300-400
- 正文 400-500
- 小字 500-600

硬规则：同一页内字号越小字重必须≥字号越大的；16px小字拒绝weight 300；主标题与正文字号比≥8:1。

最小字号底线：正文18px、卡片描述16px、meta 14px。

### 2.5 内容层级规则

| 层级 | 角色 | 风格 A | 风格 B |
|---|---|---|---|
| kicker | 本页钩子 | 衬线小标 | 无衬线 SemiBold 小标 |
| 主标题 | 页面核心结论 | 衬线超大字 | 无衬线 ExtraLight 超大字 |
| 副标题/lead | 展开说明 | 非衬线中字 | 无衬线常规字 |
| 正文 | 详细内容 | 非衬线常规 | 无衬线常规 |
| 元数据 | 栏目/页码/来源 | 等宽小字 | 等宽 uppercase 小字 |
| 引用 | 金句/他人观点 | 衬线斜体 | 无衬线大字 + 发丝线 |

kicker 与 chrome 不重复：chrome 是稳定栏目标签，kicker 是本页独有钩子。

### 2.6 数据排版规则

- 数字用 K/M 简写（110K+、5,166）
- 数据页结构：label（英文小字）→ 数字（大字）→ note（注释）
- KPI、排名、对比、时间线全部用表格呈现
- 排名表按数值降序，时间线按时间升序
- 数字后标注单位，不裸奔

## 六、五个核心工作流

### WF1 · 需求澄清与风格定位

触发：做一份 PPT、帮我设计演示文稿。

步骤：
1. 风格判断：根据用户描述自动推荐 A/B。
2. 7 问澄清（信息不足时逐项问，一次最多 3 问）：风格？受众和场景？时长？原始素材？图片需求？主题色？硬约束？
3. 叙事弧大纲：钩子→定调→主体→转折→收束。
4. 主题节奏预排。
5. 用户确认后写入 Project Spec，状态置 styled。

### WF2 · 版式规划与内容生成（排版核心）

前置：status == styled。

步骤：
1. 版式分配：从对应风格版式库选择。版式多样性硬规则：7-8页≥6种，10页+≥8种；禁止连续3页同结构。无图片模式下需图版式自动降级。
2. 主题节奏落地：每页标记 hero dark/hero light/light/dark。
3. 逐页内容生成：标题按字数分档、kicker 每页独有、数据页 label→数字→note、正文每页≤3要点。
4. 输出版式感知 Markdown。
5. 状态置 content_ready。

### WF3 · 演讲备注

每页生成稳定 slide_id。逐页填充 purpose、talk_points（3-5条）、transition、minutes。时长校验：所有页面 minutes 之和 ≤ 目标时长 × 90%。

### WF4 · 质量校验

P0 阻断级（必须全过）：
- P0-1 风格一致性
- P0-2 版式登记（风格B每页合法 data-layout）
- P0-3 版式多样性
- P0-4 主题节奏
- P0-5 标题非空且分档合理
- P0-6 数据格式（数字有单位，K/M简写）
- P0-7 kicker 不重复
- P0-8 时长预算
- P0-9 无 emoji
- P0-10 敏感内容

P0 不过 → 阻断并返回具体页码和修改建议。

### WF5 · 导出交付（含排版自动化）

前置：status == qa_passed。

1. 注入风格 CSS：在 Markdown 顶部拼接 style 块，md_to_html 保留 raw HTML，输出直接是 guizang 风格。
2. 组装完整 Markdown：CSS 块 + 每页内容。
3. 调用 md_to_html：输出高保真 HTML（主交付物）。
4. 调用 md_to_pptx：输出 PPTX。
5. 检查返回：isError == false，从 files[].url 取下载链接。
6. 生成一次性主题设置卡：精确到点击路径的主题色/字体设置步骤，用户只需做一次。
7. 可选：python-pptx 自动套主题（如平台支持代码执行）。
8. 打包交付：PPTX + HTML + 一次性设置卡 + 演讲备注 + 校验报告。

## 八、Markdown 转换器插件集成

### 8.1 工具选择

| 工具 | 用途 |
|---|---|
| md_to_html | 主交付格式（已验证保留 style 标签） |
| md_to_pptx | PPTX 备选（效果有限） |
| md_to_docx | 演讲备注导出（可选） |

### 8.2 排版自动化策略（四层）

手工逐页调整 15 页 deck 需 1-2 小时。通过四层自动化压缩到 5 分钟：

第一层：Markdown 内嵌 CSS → HTML 输出 100% 自动 styled。md_to_html 保留 raw HTML，输出直接应用 guizang 风格。用户对 HTML 零调整。

第二层：Markdown 结构优化 → PPTX 默认渲染即接近版式。表格=数据版式、blockquote=引用、H1=大标题。

第三层：一次性主题设置卡 → PPTX 全局生效。视图→幻灯片母版→颜色→自定义颜色→色值；字体同理。用户只做一次，约5分钟。

第四层（可选）：python-pptx 自动套主题。如平台支持代码执行，连5分钟都省略。

### 8.3 已验证的技术约束（9轮测试确认）

- style 标签保留、class选择器正常、大写hex正常、font-family:sans-serif正常
- 单引号会截断输入、小写hex会被插空格、元素选择器h1/h2会被插空格
- 总长度约1000字符边界，必须多行格式每行一条CSS
- 正确方案：CSS放系统提示词，用户用自然语言描述需求，智能体自主生成

详见 docs/04-技术验证记录.md。

### 8.4 手工调整工作量对比

| 方案 | 15页deck手工时间 |
|---|---|
| 逐页手动调整（旧） | 60-120 分钟 |
| 三层自动化（新） | 5 分钟 |
| 四层自动化（含python-pptx） | 0 分钟 |
