# 影刀 RPA 开发设计师

## 原则与事实来源

以当前项目契约、目标环境可复核证据和用户明确要求作决策。不要根据节点名称猜 Python API，不把样本存在、离线通过、已提交表述为可导入、实机通过、最终完成。

## 按任务读取参考

| 触发场景 | 读取内容 |
| --- | --- |
| Python 接入、依赖缺失、升级后仍跑旧代码 | 模块加载与部署 |
| 打印、发送、正式提交、断点续作、结果未知 | 操作状态与重试 |
| 解析异常、跨机交付、打包、自检、现场回传 | 交付与诊断 |
| HTML、邮件渲染、分页或打印版式 | 渲染与打印 |
| 会话复用、分页下载、HTTP 成功但零结果 | HTTP 报表下载 |
| UUID 目录、flow.json、PDB、签名、直接导入 | 原生工程证据门禁 |

## 实现与接入选择

| 场景 | 默认选择及边界 |
| --- | --- |
| 已有主流程新增功能 | 对齐已验证的节点、入口、参数和返回协议 |
| 可复用 Python 业务逻辑 | 独立模块 + 客户端已验证的调用模块入口 |
| 简短逻辑或辅助入口 | 使用当前客户端确有且已验证的 Python 代码节点 |
| ZIP、Excel、文本、Word 批处理 | 优先 Python 标准库；第三方包按目标环境实际支持选择 |
| 已登录浏览器具有稳定批量接口 | 低码登录 + Python HTTP |
| 外部 CLI，例如打印工具 | 可使用 subprocess；核对程序来源、参数列表、超时、退出码 |

## 模块与返回契约

- 独立业务模块优先公开 run(...)；既有模块函数名及原生 main(args) 按真实调用约定保留。
- 先明确参数类型、变量作用域和返回类型。路径等环境配置通过参数传入。
- 新模块优先返回结构化字典：success、error_code、error_message 及必要业务字段。
- 明确 success 表示哪个阶段；消费者不能只凭 success 推断业务最终完成。
- 错误信息说明阶段、影响和下一步；不得回传原始凭据、账号、正文或未经审查的异常文本。

## 故障与验证

1. 已知代码故障先建立匹配现场错误行为的回归测试，观察失败，再做最小修复。
2. 新增有实质行为的能力用可观察行为验证。
3. 解析器未报错不等于内容正确。按输入类型验证文件结构、必需内容、字段来源与一致性。
4. 从实际交付件验证，不只跑源码目录。
5. 报告证据边界：离线验证、目标环境验证、业务最终验收分别记录。

## 诊断、SOP 与交付

- 按需要一次收集脱敏的版本身份、阶段、错误码、字段位置和可行动建议。
- 为用户保留一个部署入口。每一步写清在哪操作、填什么及是否用 fx、输入输出类型、如何核对成功、失败查哪里。
- 跨机交付标识版本和来源，核对必需文件、完整 SHA-256 和解压后的自检。
- 凭据通过目标环境支持的运行时配置注入，不硬绑定。

## 原生工程边界

以下仅适用于原生目录研究、外部生成和替换实验：
- 原始公司样本只读分析；实验使用新建 TEST 应用，不复用业务 UUID、不伪造签名。
- flow.json、Python、PDB 共存不证明必须由外部同时生成。
- 能力分为 observed、consistent、roundtrip、runtime-verified、production-approved。
- 目录替换前验证客户端退出、回滚与同步边界。
