# 影刀原生工程证据门禁

## 1. 已观察结构

一个公司环境 UUID 应用样本包含：
- xbot_robot/package.json：流程、流程组、全局变量、Python 与内部组件依赖
- xbot_robot/package.py：选择器、资源和全局变量访问入口
- xbot_robot/*.py：可视化流程生成代码和 Code 流程源码
- xbot_robot/.dev/*.flow.json：可视化节点、参数、输入输出和启停状态
- xbot_robot/.dev/*.pdb：代码行与节点的调试映射
- selectorsV2.xml、.dev/screenshot/、resources/：元素与资源
- xbot_extensions/：内部扩展缓存，可能包含签名和加密流程
- venv310/、databook.db3：运行环境和数据表

已观察样本为 24 个流程、663 个节点实例和 69 种节点。

## 2. 不能直接推断的事项

- UUID 目录是否会被客户端自动注册
- package.sigstore 的算法和校验时机
- .flow.json、.py、.pdb 哪些是源文件、哪些是派生文件
- 复制内部扩展目录能否替代客户端安装和授权
- authority: view 是否允许编辑、保存或重新发布
- 原应用中的闲置流程、未声明变量和未使用选择器是否仍可运行

## 3. 证据等级

| 等级 | 含义 | 允许的说法 |
| --- | --- | --- |
| observed | 只在文件中出现 | 样本中观察到 |
| consistent | 交叉引用和静态检查一致 | 结构静态一致 |
| roundtrip | 同版本客户端能打开、保存并重新生成 | 客户端可回读 |
| runtime-verified | TEST 应用能运行、保存、关闭并重开 | 目标版本已验证 |
| production-approved | 经审批在生产范围验证 | 可用于批准的生产场景 |

自动生成白名单至少要求 runtime-verified。声称可导入还要求官方导出件完成另一测试应用的重新导入。

## 4. 安全差分取证

使用公司客户端新建的独立 TEST 应用，依次生成：A 空白应用、B 增加固定日志和消息、C 增加全局变量/条件/子流程、D 增加无敏感信息的本地测试网页元素。

每一步都从客户端正常保存，彻底退出后复制快照。禁止使用原业务 UUID、业务选择器、真实凭据、内部网页。

## 5. 编译路线选择

1. 官方导出件可修改并重新导入：Direct Import Compiler
2. 必须由客户端保存或签名：本地 Build Pack + 公司端 Client Finalizer
3. 目录是唯一机制且注册/回滚已证明：带备份和原子恢复的安全安装器
4. 以上都不可行：交付 Python 业务模块 + 公司客户端创建的最小可视化壳

## 6. 交付验收

- TEST 应用能显示、编辑、运行、保存、关闭和重开
- 流程自身无网络连接、无生产写入、无测试目录外文件改动
- 其他应用和目录哈希不变
- 失败后可以完整恢复
- 交付件、日志、Git 和 skill 均无真实业务数据或凭据
