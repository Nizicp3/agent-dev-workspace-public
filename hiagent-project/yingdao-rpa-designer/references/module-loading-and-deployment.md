# 模块加载与部署

适用：接入既有影刀流程、运行时依赖、缓存或跨机版本不一致。

## 先确认接入契约

记录已有节点名称、模块/函数、参数类型、变量作用域、输出类型和下游条件。复用现有主入口；仅在确有独立排障需求时增加薄辅助入口。

环境相关路径通过参数或项目配置传入；模块不读流程全局变量作为隐式依赖。

## 区分三种环境

检查系统终端、影刀节点、被启动的外部程序各自的运行时与依赖：Python 版本、执行方式、工作目录、模块实际来源、必需依赖及版本、外部工具绝对路径。

返回脱敏摘要即可。不能从某次客户端行为推断所有影刀都只复制入口。

## 加载策略

1. 原生包导入在目标环境已验证时继续使用。
2. 若平台确实复制入口而不复制依赖，明确真实交付根目录及资源布局。
3. 加载前检查必需文件；加载后核对模块来源和版本。
4. 已证实缓存旧版本时，优先采用客户端支持的重载/重启。
5. 必须动态加载时，限定应用自己的命名空间、依赖和生命周期。

Python 删除 sys.modules 项不会删除其他对象持有的旧引用；reload 也不会自动更新外部引用。

## 身份核验与 CLI

跨机升级或缓存环境比较：源码版本 → 解压交付件 → 实际加载入口及关键模块。必要时返回 module_fingerprint 和预期对比。

调用外部程序是 subprocess 的合理用途。优先参数列表、明确可执行程序和工作目录，检查超时、返回码、stdout/stderr。
