## 2. 优先级最高的三个代码问题

### C01：字符串 False 被当成真（P0）

15 个 Code 节点均新增 _orig_handler 外层包装，把所有非字符串输出变成 str(v)。因此 False 变为字符串 "False"，下游还在使用 if value，会把非空字符串当成真。

本地真实执行后已复现：
- ②输入六维度缺失：all_covered="False"，但 needs_user_confirmation="False"
- ④打包输入 import_ready="False"：返回标志 False，但正文写导入就绪：是
- ⑥预检输入 all_compiled="False"、generated_yamls="[]"：all_import_ready="True"、检查数量 0

**优化任务：** 保留平台已配置的字符串接口时，在每个消费者入口显式解码；输出时将布尔值规范序列化为 "true"/"false"。接受原生 bool 和规范化后的 true/false（迁移时兼容 True/False）；缺失、空值和其他文本返回输入格式错误。

### C02：④仍生成不完整的工作流（P0）

附件④的确定性YAML结构生成仍只输出 Start/Code/LLM/Code/End 五个节点的 Type 与 Name。没有业务代码、模型提示词、ID、Configs、变量映射及完整原生外壳。节点类型合法检查固定为 True。

**优化任务：** 将已有 generator/hiagent_workflow.py 的受控规格校验、原生构建和序列化逻辑接入④。首期目标：只生成一个可复用模板族的邮件待办提取工作流。

### C03：需求完整性与最终确认不是一回事（P0）

②仍用关键词命中判断完整性，且仅在不完整时设置 needs_user_confirmation。即使需求完整，用户仍应最终确认。

**优化任务：** 拆成 needs_clarification、needs_final_confirmation、confirmed_revision。用户确认只对当前版本有效。否定或修改后旧确认失效。

## 4. 主 Agent 可在界面执行的优化

### A01：保留对话型，不重新创建
- 记录模型、温度、最大输出、挂载工作流版本。
- 将当前人设与回复逻辑另存为回退副本。
- 给每个工具描述补充用途、所需输入、成功/失败字段。

### A02：合并到现有提示词

核心规则：每次只提一个能改变工作流设计的问题；已明确的事项不重复询问；需求整理完成后必须展示目标、范围、输入输出、人工确认点、异常处理与验收标准，等待用户明确确认；用户否定或修改时不推进生成；无效方案选择不默认选第一个。

状态与工作流：维护项目编号、需求版本、已确认事实、材料来源、未决冲突；调用工作流前核对输入；返回失败时说明具体问题，不宣称已完成。

交付：仅在有效结构预检通过时标记可导入版本，待公司环境验证；生成文件导入成功与业务运行通过分别记录；YAML保持工具返回原文，不重新改写。
